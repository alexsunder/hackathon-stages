# Инструкция агенту: из чата и чеков → ledger.csv

Шаг 1 из 2. Агент читает сырые данные поездки и заполняет `ledger.csv`. Шаг 2 — `settle.py` считает и проверяет. Считать в уме на шаге 1 не нужно.

## Колонки ledger.csv

| Колонка | Что писать |
|---|---|
| id | L01, L02… |
| date | дата чека `ГГГГ-ММ-ДД` (для возврата — дата возврата) |
| payer | кто заплатил; для возврата — кому вернули деньги |
| amount | сумма в валюте чека, точка как разделитель; возврат — с минусом |
| currency | RUB, CNY, … |
| participants | на кого делится, через `;`, всегда поимённо |
| status | `учтено` · `личное` (не делим) · `спорное` (нет суммы/подтверждения — не решаем молча) |
| refund_of | для возврата — id исходной траты |
| description | что это |
| sources | все чеки и сообщения про эту трату через `;` (R04;M06;M10) |
| comment | почему так решили; для дубля начинать с `Дубль:`. Если есть запятая — весь текст в кавычках |

## Правила

1. Одна строка = один реальный платёж. Фото чека, текст чека и «скинул чек» про одно и то же — это ОДНА строка со всеми ссылками. Признак дубля: совпадают дата, плательщик, сумма.
2. Каждый чек из папки должен попасть хотя бы в одну строку (в любом статусе).
3. Участников берём из чата: «меня не было», «на четверых», «это моё» — меняют список или статус.
4. Возврат делится на тех же, что и исходная трата.
5. Курсы — в `rates.csv` (date,currency,rub_per_unit,source), по одному на дату. Источник курса — сообщение или внешний курс ЦБ, указать в source.
6. Сомнение → `спорное` + объяснение в comment. Не угадывать суммы.
7. Обещания без суммы, «я уже вернул» без подтверждения, расходы организатора, не сходящиеся с чеками — всё в `спорное`.
